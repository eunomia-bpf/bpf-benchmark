# kinsn fixes correctness review - 2026-05-05

Scope: review-only, current `main` worktree. The relevant project rule is that verifier safety is not pass correctness: the kernel verifier keeps the kernel safe, while userspace transforms must preserve program semantics (`docs/kernel-jit-optimization-plan.md:79-85`). The review also applies the fail-fast and unit-test quality rules in `CLAUDE.md:70-84`.

## rotate

**Verdict: SUSPECT.** The rotate transform emitted for matched sites is semantically correct and verifier-representable, but the landed fix also relies on a daemon `changed=false` fast path that now trusts the bpfopt report without comparing bytes (`daemon/src/commands.rs:724-744`). That is a concrete silent-failure risk if any pass mutates output while reporting unchanged.

1. The code emits correct rotate bytecode for the sites it still matches. The matcher requires an adjacent provenance `MOV tmp, dst` (`bpfopt/crates/bpfopt/src/passes/rotate.rs:215-228`), complementary ALU64 shifts whose amounts sum to 64 (`bpfopt/crates/bpfopt/src/passes/rotate.rs:248-255`, `bpfopt/crates/bpfopt/src/passes/rotate.rs:301-305`), and an OR combining exactly the two shifted registers (`bpfopt/crates/bpfopt/src/passes/rotate.rs:262-265`, `bpfopt/crates/bpfopt/src/passes/rotate.rs:312-314`). Emission encodes `dst`, original value reg, shift amount, and scratch reg in the packed payload (`bpfopt/crates/bpfopt/src/passes/rotate.rs:134-140`), while the x86 kinsn rejects `tmp == dst` or `tmp == src` and instantiates the same move/shift/or proof sequence (`module/x86/bpf_rotate.c:16-31`, `module/x86/bpf_rotate.c:35-56`). The tetragon unblock itself was mostly the daemon no-op skip: the prior fix doc says rotate had `sites_applied` 0 before and after, and the remaining effect was avoiding identical-bytecode ReJIT (`docs/tmp/rotate-tetragon-fix-20260505.md:34-55`).

2. Tightening the matcher loses semantically valid rotate idioms. First, `mov tmp,val; rsh tmp,56; lsh val,8; or tmp,val` is a valid rotate result in `tmp`, but `rotate_site` rejects every `dst_reg == tmp_reg` site because the packed ABI cannot use the result reg as proof scratch (`bpfopt/crates/bpfopt/src/passes/rotate.rs:345-363`). Second, any independent instruction between provenance and shifts is rejected because `find_provenance_mov` only checks `shift_pc - 1` (`bpfopt/crates/bpfopt/src/passes/rotate.rs:219-228`); the test explicitly rejects `mov tmp,val; mov r5,r6; rsh...; lsh...; or...` (`bpfopt/crates/bpfopt/src/passes/rotate.rs:737-749`). Third, any independent instruction between the two shifts and OR is outside the three-instruction scan window (`bpfopt/crates/bpfopt/src/passes/rotate.rs:198-204`). These are missed optimizations, not wrong transforms.

3. It is legitimate for bpfopt to report `changed=false`; each pass returns `PassResult::unchanged` when no safe site exists (`bpfopt/crates/bpfopt/src/pass.rs:509-518`), and rotate does that when `safe_sites` is empty while preserving skip reasons (`bpfopt/crates/bpfopt/src/passes/rotate.rs:110-115`). The current daemon, however, reads the pass output and immediately reports `PassStatus::Unchanged` if `report.changed` is false, without decoding or comparing `pass_bytes` to `current_bytes` (`daemon/src/commands.rs:724-744`). Concrete trigger: a bpfopt bug that writes a sidecar+call but leaves `changed=false` will be silently ignored by the daemon, no ReJIT will occur, and no error will surface. The old byte-equality sanity check described in the fix doc is not present in the current file (`docs/tmp/rotate-tetragon-fix-20260505.md:9-12`, `daemon/src/commands.rs:736-744`).

Failure shapes if left as-is: a false-negative bpfopt report (`changed=false`, output bytes changed) silently drops a transform at the daemon boundary; a valid rotate writing the result into the copy register is silently not optimized; a valid rotate with side-effect-free intervening instructions is silently not optimized (`daemon/src/commands.rs:736-744`, `bpfopt/crates/bpfopt/src/passes/rotate.rs:353-355`, `bpfopt/crates/bpfopt/src/passes/rotate.rs:215-228`).

Suggested follow-up: restore a fail-fast byte equality check on the daemon no-op path, or derive no-op status from `pass_bytes == current_bytes` before trusting the report (`daemon/src/commands.rs:724-744`). No rotate bytecode revert is needed.

Over-engineering/dead code to delete: 0 LoC. The `SafeRotateSite` wrapper is thin but harmless (`bpfopt/crates/bpfopt/src/passes/rotate.rs:188-190`); deleting it would be cleanup, not a correctness fix.

## cond_select

**Verdict: SUSPECT.** The immediate materialization logic is mostly coherent for straight-line first-run lowering, but temp selection is pass-local liveness rather than verifier-state-driven, and the generic predicate prefix is not idempotent.

1. The pass does not consult verifier-state register-class info. It reads `live_after` from `LivenessAnalysis` after the original site (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:149-168`), and that analysis is a local bytecode fixed-point dataflow over syntactic successors (`bpfopt/crates/bpfopt/src/analysis/liveness.rs:25-56`, `bpfopt/crates/bpfopt/src/analysis/liveness.rs:123-141`). `choose_temp_reg` then picks `dst_reg` first, otherwise any BPF reg 0-9 not in `forbidden`, not already allocated, and not syntactically live after the site (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:610-623`). That is stronger than a five-instruction lookahead, but it is still not verifier-state liveness or register-class proof.

2. The exact tail-call example is blocked today: every kinsn replacement calls `kinsn_replacement_subprog_skip_reason`, and that rejects any program containing a tail-call helper (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:198-203`, `bpfopt/crates/bpfopt/src/passes/utils.rs:773-808`). The remaining concrete risk is BPF-to-BPF subprogram liveness: `LivenessAnalysis` treats calls as using r1-r5 and defining r0-r5 only (`bpfopt/crates/bpfopt/src/analysis/liveness.rs:93-102`), and its successor model does not walk into `BPF_PSEUDO_CALL` callees (`bpfopt/crates/bpfopt/src/analysis/liveness.rs:123-141`). A valid assembly-shaped trigger is: caller sets r6, a cond_select site with `dst == cond == r0` and immediate arms forces r0 forbidden and r1-r5 live through a following call, `choose_temp_reg` picks r6, then a BPF-to-BPF callee reads r6. The original site only wrote r0; the rewrite can clobber r6 before the call (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:423-441`, `bpfopt/crates/bpfopt/src/passes/cond_select.rs:573-599`, `bpfopt/crates/bpfopt/src/passes/cond_select.rs:610-623`).

3. The non-zero `JEQ/JNE` construction is correct for JMP64 and deletes the original compare. For `JEQ/JNE reg, imm` in BPF_JMP class, the pass copies `cond_reg` into a temp, XORs the immediate, and swaps true/false operands for `JEQ` so `select(cond != 0)` preserves the original branch sense (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:487-502`, `bpfopt/crates/bpfopt/src/passes/cond_select.rs:416-421`). For `JMP32 reg, 0`, it first materializes the low 32 bits with `mov32_reg` before using the packed select predicate (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:471-485`, `bpfopt/crates/bpfopt/src/passes/cond_select.rs:601-608`). For non-zero JMP32 and other compares, it keeps the compare class/opcode in a new predicate-building prefix and deletes the original site (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:505-554`, `bpfopt/crates/bpfopt/src/passes/cond_select.rs:235-248`). The old compare is not kept in place; the original site is skipped by `pc += site.old_len` during rewrite (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:235-249`).

4. The over-target LoC is real and concentrated in speculative generic predicate support. The immediate task requires materializing `Imm`/`Imm32` and `Reg32` values (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:573-599`); the broad non-JEQ/JNE predicate builder and inverse-op table add about 65 implementation LoC (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:505-571`) plus a generic JGT test (`bpfopt/crates/bpfopt/src/passes/cond_select_tests.rs:457-479`). This code also creates the idempotence defect: for `JGT`, the first pass emits `mov pred,0; JLE +1; mov pred,1; sidecar; call` (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:513-527`, `bpfopt/crates/bpfopt/src/passes/cond_select_tests.rs:457-479`), and the scanner recognizes that three-instruction prefix as Pattern C on a second run (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:334-381`).

Failure shapes if left as-is: a BPF-to-BPF caller whose callee reads a callee-saved register that is not syntactically live in the caller can be clobbered by immediate materialization; a program containing `JGT/JLE/JSGT/...` cond_select sites is not idempotent because the generated predicate prefix is itself a cond_select pattern (`bpfopt/crates/bpfopt/src/analysis/liveness.rs:93-102`, `bpfopt/crates/bpfopt/src/passes/cond_select.rs:505-554`, `bpfopt/crates/bpfopt/src/passes/cond_select.rs:334-381`).

Suggested follow-up: either drive temp selection from verifier/callchain-aware liveness, or conservatively avoid callee-saved temps before reachable BPF-to-BPF calls; also make generic predicate lowering unmatchable on a second run or delete the generic compare expansion and keep only JEQ/JNE immediate support (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:505-571`, `bpfopt/crates/bpfopt/src/passes/cond_select.rs:610-623`).

Over-engineering/dead code to delete: about 65 LoC in `bpfopt/crates/bpfopt/src/passes/cond_select.rs:505-571` and 23 LoC in `bpfopt/crates/bpfopt/src/passes/cond_select_tests.rs:457-479` unless generic compare support is made idempotent.

## endian

**Verdict: CORRECT.** For emitted sites, the DW/W narrowing rewrite is conservative and semantics-preserving. The main issues are missed coverage and weak diagnostics, not wrong bytecode.

1. The upper-bit proof is actually a conservative whole-register check. `blocks_narrow_window` rejects any intervening barrier, read, or write of the loaded destination (`bpfopt/crates/bpfopt/src/passes/endian.rs:201-203`), and `reads_reg` treats source-register use, ALU/ST/STX destination use, conditional-jump destination use, LDX base use, calls, and exits as reads (`bpfopt/crates/bpfopt/src/passes/endian.rs:209-220`). This is stricter than an upper-bit-only proof and correctly avoids moving a narrowed load ahead of any observation of the original wide loaded value.

2. The 32-instruction window is arbitrary as implemented. The only justification in code is `const MAX_NARROW_SCAN: usize = 32` (`bpfopt/crates/bpfopt/src/passes/endian.rs:32-33`), and the scanner stops at `pc + MAX_NARROW_SCAN + 1` (`bpfopt/crates/bpfopt/src/passes/endian.rs:92-108`). A valid `LDXDW; ... 33 independent insns ...; be32 dst` candidate is silently not matched. The prior investigation found 32 static non-strict `LDXDW + be16/be32` source pairs, but it did not measure how many live candidates had distance >= 32 (`docs/tmp/kinsn-low-apply-investigation-20260505.md:139-161`).

3. The rewrite correctly handles intervening instructions and rejects same-register writes before rewrite. The matcher stops before a non-adjacent narrowed endian op if any intervening instruction writes the loaded destination (`bpfopt/crates/bpfopt/src/passes/endian.rs:105-108`, `bpfopt/crates/bpfopt/src/passes/endian.rs:222-227`). For accepted non-adjacent sites, emission replaces the load with the fused packed call, copies only the safe intervening instructions, deletes the final endian op, and maps the deleted endian PC to the end of the replacement window (`bpfopt/crates/bpfopt/src/passes/endian.rs:503-524`, `bpfopt/crates/bpfopt/src/passes/endian.rs:562-575`).

4. The 4-to-5 smoke result does not prove the conservative check is too conservative. The Cilium artifact contains 61 endian pass reports: 56 with zero sites and 5 with one applied site, all with `sites_skipped: 0` and empty `skip_reasons` (`corpus/results/x86_kvm_corpus_20260505_151506_347859/details/apps/cilium__agent.json:1650-1660`, `corpus/results/x86_kvm_corpus_20260505_151506_347859/details/apps/cilium__agent.json:2322-2332`, `corpus/results/x86_kvm_corpus_20260505_151506_347859/details/apps/cilium__agent.json:2546-2556`, `corpus/results/x86_kvm_corpus_20260505_151506_347859/details/apps/cilium__agent.json:2770-2780`). No `narrow endian` or `upper bits` diagnostic appeared in daemon logs, and the previous investigation already warned that static object PCs do not reconcile reliably with live bytecode (`docs/tmp/kinsn-low-apply-investigation-20260505.md:158-170`). The likely explanation is live-bytecode/object mismatch and limited loaded Cilium coverage, not an unsafe conservative check.

Failure shapes: no confirmed semantic mis-transform. Missed-match shapes are `LDXDW/LDXW` followed by a narrowed endian after 33+ safe straight-line instructions, or after a barrier/write that should be reported but is not (`bpfopt/crates/bpfopt/src/passes/endian.rs:92-108`, `bpfopt/crates/bpfopt/src/passes/endian.rs:162-199`).

Suggested follow-up: measure live bytecode distances before changing `MAX_NARROW_SCAN`; if diagnostics matter, record skip reasons for window overflow, barriers, and writes in `find_blocked_narrow_sites` (`bpfopt/crates/bpfopt/src/passes/endian.rs:162-199`). No revert is needed for semantic correctness.

Over-engineering/dead code to delete: 0 LoC. The diagnostic scanner is imperfect but has a real caller and feeds `sites_skipped` (`bpfopt/crates/bpfopt/src/passes/endian.rs:162-199`, `bpfopt/crates/bpfopt/src/passes/endian.rs:399-402`).

## Cross-cutting

No silent failure: rotate has a real daemon silent-failure trigger because `changed=false` bypasses byte comparison and ReJIT (`daemon/src/commands.rs:724-744`). Cond_select and endian record explicit skip reasons for no temp/kfunc/interior-target cases (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:168-176`, `bpfopt/crates/bpfopt/src/passes/endian.rs:403-470`), but endian does not report all blocked narrowing candidates (`bpfopt/crates/bpfopt/src/passes/endian.rs:162-199`).

Idempotence: rotate and endian are idempotent because their outputs do not contain their source patterns (`bpfopt/crates/bpfopt/src/passes/rotate.rs:131-145`, `bpfopt/crates/bpfopt/src/passes/endian.rs:503-524`). Cond_select is not idempotent for the generic predicate prefix because the first pass emits a Pattern C-shaped `MOV; Jcc +1; MOV` prefix, and the scanner accepts that same shape (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:513-527`, `bpfopt/crates/bpfopt/src/passes/cond_select.rs:334-381`).

No fallback: the three fixes skip or error rather than lowering with less-safe logic. Rotate records live-out/interior/subprog skips before emission (`bpfopt/crates/bpfopt/src/passes/rotate.rs:63-107`); cond_select returns a skip reason when no predicate/value temp is available (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:168-176`, `bpfopt/crates/bpfopt/src/passes/cond_select.rs:573-599`); endian checks kfunc, packed ABI, branch targets, subprog boundaries, and size-specific call offsets before emission (`bpfopt/crates/bpfopt/src/passes/endian.rs:403-470`, `bpfopt/crates/bpfopt/src/passes/endian.rs:497-501`).

Tests: rotate has a regression test for the unsafe `OR`-writes-temp shape (`bpfopt/crates/bpfopt/src/passes/rotate.rs:445-455`), but no daemon unit test asserts that `changed=false` output bytes equal input bytes (`daemon/src/commands.rs:1551-1607`). Cond_select immediate and compare tests exercise old rejected shapes and are not trivial getter tests (`bpfopt/crates/bpfopt/src/passes/cond_select_tests.rs:276-479`), but there is no idempotence or BPF-to-BPF temp-liveness regression. Endian has a real narrowing and blocked-read regression test (`bpfopt/crates/bpfopt/src/passes/endian.rs:794-840`), but no 33+ window or same-dst-write diagnostic test.

Aggregate severity: **1 CORRECT / 2 SUSPECT / 0 WRONG**.

Top 3 highest-risk shapes:

1. `cond_select` before a BPF-to-BPF call where only the callee reads a callee-saved register chosen as an immediate temp; current liveness does not model callee bodies (`bpfopt/crates/bpfopt/src/analysis/liveness.rs:93-102`, `bpfopt/crates/bpfopt/src/passes/cond_select.rs:610-623`).
2. `cond_select` generic compare sites such as `JGT/JLE/JSGT` that emit a predicate prefix re-matched by the same pass on a second run (`bpfopt/crates/bpfopt/src/passes/cond_select.rs:505-554`, `bpfopt/crates/bpfopt/src/passes/cond_select.rs:334-381`).
3. Any bpfopt pass that writes changed bytecode while reporting `changed=false`; the daemon records `Unchanged` and never ReJITs the candidate (`daemon/src/commands.rs:724-744`).

Revert recommendation before SAMPLES=30 authoritative run: do **not** make a revert/restore commit. Fix forward before the paper run: restore the daemon no-op byte check and fix or temporarily remove the cond_select generic compare expansion. Endian DW-narrowing does not need to be reverted.
