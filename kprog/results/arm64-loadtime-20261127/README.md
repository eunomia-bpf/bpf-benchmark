# ARM checked loading time

The profile target replays the recorded slowest completed Cilium frontend at its original canonical source/output paths, with its original B flags plus compiler time-report/trace diagnostics. The original service archive retains earlier products. It records frontend IR and B executable-byte comparisons, compiler resource use and complete profiling diagnostics.

The additional compiler uses CPU 18 and a 48-GiB address-space cap while the existing Tetragon compiler uses CPU 16. Production headers, binaries and the active Tetragon process retain their current code. This is diagnosis for one common loading repair across every app; complete frozen Cilium startup/post validation remains the delivery target.
