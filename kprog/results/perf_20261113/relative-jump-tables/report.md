# Relative jump-table relocation binding

The unified compile flags produce a PC32 LEA of a read-only table, MOVSXD of an indexed32-bit entry, ADD of the table base and register JMP. The old proof copier copied the zero table bytes while dropping their relocations; the generic kernel path rejected the register jump. The normal linker now preserves nested PC32 code relocations in `.native_link_rodata`, translating source instruction boundaries to the rewritten proof layout and preserving each slot's bias. Kernel linking resolves the same entries again after its own instruction layout. These relative entries need no new kernel relocation or loader ABI. No switch or old alternative is retained.

Only matched table sequences with an actual PC32 code entry at their base bypass generic indirect-branch rejection. Malformed or removed/interior code targets error; a different jump register and an unsupported first relocation do not authorize a table jump. The diagnostic no longer asks users to disable jump tables. Other table forms, absolute memory references, cross-function reachability and compiler-generated immutable map-pointer tables remain work.
