# Load, verifier and JIT transformations to join per program

Source-anchors.json retains file SHA, actual line matches and the current kernel submodule identity. programs.json references these six dimensions for every staged row. Current runtime evidence belongs to its captured image/kernel, so this source map is not an installed-code or equality verdict.

| Dimension | eBPF kernel and loader behavior | Native evidence now | Remaining per-program evidence |
| --- | --- | --- | --- |
| Frozen globals | The app writes internal data maps before freezing; verifier/JIT sees actual read-only values and can remove branches. | Common frozen_ir.rs consumes live scalar values and retained IR on both ISAs; host14 regressions and ARM compiler/linker execution passed. All114 staged objects retain IR. | Live map flags/frozen state/BTF offset/value in the plan, then actual removed branch/call with mutable globals still referenced. ARM OTel1278576 currently collecting this. |
| Context | convert_ctx_access and program-type access validation translate public context fields into actual kernel layout; tracing/probe accesses can differ. | Existing x86 loader context/function LTO is guarded by __x86_64__ and passes actual prog type. Common ARM frozen pass is not evidence of all context rewrites. Existing OTel native sampling code explicitly dereferences bpf_perf_event_data_kern.regs in tracemgmt.h. | Actual attach type, field offsets, source accesses and installed native/JIT accesses for every loaded program. Audit ARM contexts beyond the existing sampling adapter; do not broaden frozen loader core based on source asymmetry alone. |
| Helpers | do_misc_fixups substitutes map ops/gen_lookup and jiffies; x86 per-CPU/current-task helpers are inlined there. ARM JIT separately inlines CPU and current-task from sp_el0. | ARM linker emits matching sp_el0/current-task and thread_info.cpu sequences; generic helper calls and site-specific map paths also exist. Direct entry relocation names retained per row. | Resolve actual helper addresses, map shape and relevant transitive calls in the live plan/installed code. Equivalent generic dispatch versus inlining alone is a cost difference, not a semantic bug. No speed work. |
| Tail calls | Verifier/JIT uses prog-array map, bounds/depth rules and architecture frame convention; taken tails can bypass normal per-program stat entry. | Existing ARM tail inline uses live offsets and fixed x26/frame restoration. Program declarations and direct entry references retained. | Actual slot-to-program IDs, current native/BPF targets, taken work and unwinder counters; zero tail-program run_count is not non-execution. |
| Map dispatch | Map pseudo references bind to the app's actual FD/ID/type/shape; gen_lookup and ops dispatch use that map. Kernel names truncate to15 bytes. | Common LPM producer/consumer cut-name binding fix and unique/ambiguous alias regressions passed. Object collision groups retained, including Cilium/Tetragon groups. | Original object/source map identity plus live ID/type/shape and per-site plan. Keep unknown/ambiguous handling general; no arbitrary prefix selection. |
| App switches/constants | Actual selected source, app compile macros and user-space loader-written values determine work. They can differ even with identical workload processes. | Exact embedded native compile commands where available; actual merged OTel IR CPU/tune attributes; per-row object/manifest SHA. Current vendor/bpf/Makefile common codegen flags and app source options are anchored. | Compare with the current app's selected eBPF object and generated configuration, then join load-time constants and work. The previous x86 six-app work checks establish engagement with documented limits, not full feature parity. |

Additional kernel transformations remain part of the same semantic audit: divide/modulo zero and signed overflow handling, arithmetic width/zext, probe/user-address protection and exception tables, speculation barriers, kfunc/CO-RE/function relocation and trampoline/attach ABI. Verifier.c do_misc_fixups contains concrete arithmetic and probe rewrites. The census does not assert native counterparts or actual use; investigate only the programs/operations evidenced by current objects and loads, preserving the original kernel/framework/settings. No hypothetical guard, selector or new test framework is introduced.
