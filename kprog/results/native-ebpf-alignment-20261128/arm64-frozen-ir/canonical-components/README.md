# Canonical ARM toolchain component build

The existing vendor Makefile must build a compiler that executes on the requested architecture. Its old host-clang++ rule silently placed an x86 executable in the arm64 stage. The necessary repair selects cross-g++ and the proven existing canonical ARM base LLVM18/libbpf for ARCH=arm64; x86 keeps its previous compiler and static-link flags. There are no app flags, new backend versions, SDK downloads, runtime guards or alternate production modes. Makefile is an explicit target dependency so a build-policy change cannot leave the old wrong-ISA file considered current. This route requires the already-established canonical ARM base at .cache/qemu-arm64-root.

build.sh runs that precise canonical component target and the native-link-only cross-Rust command/flags from runner/mk/build.mk. No kinsnprober, P, kernel, benchmark or image target is invoked. build_components.py takes timingSH/imageEX, applies48GiB/max2/CPU16,18 to build children, saves the prior tools and records the sole kernels/all non-tool ARM stage inputs and current image before/after. The original compiler's actual ARM execution and normal proof receipt are already accepted in the parent directory; byte identity is recorded after the canonical rebuild. The newly built ARM native-link is actually run under installed qemu-aarch64-static on the same compiler-output fixture, and its proof ABI/immutable branch/live-global references are checked. Whole-proof equality to the x86-host linker output is reported separately.

This is component and actual ARM userspace execution evidence, not a native kernel guest run or image activation.
