# Captured native tail-call instruction attribution

This reader uses the three existing verified evidence archives and retained 324-plan report. It reads every canonical cache blob, verifies its archive member size/SHA, joins its exact architecture/app/cache key to the captured plan and finds emitted tail-call instruction blocks. Identical blocks share one disassembly, with every blob/site offset retained in one consolidated result. Both x86 six-app captures and the legacy ARM OTel capture are included; this adds no new guest run or benchmark variant.

Source inspection found matching unsigned index32 bounds, a 33-call shared counter limit and counter storage only after a non-null program slot in the native and kernel implementations. The ARM JIT increments its temporary earlier but stores the shared count only after the null-slot check. The actual generated ARM config enables kernel PAC and omits kernel BTI, giving PROLOGUE_OFFSET seven instructions / 28 bytes, matching the captured ARM plan entry offsets inspected so far. x86 captured plans use entry offset12. Full current source hashes/fragments and actual generated config hashes accompany the result.

The reader records candidate instruction details, branch destinations and diagnostics without assuming a site count or converting signature absence into no-tail execution. A variant disassembly is actual captured bytes. The signature recognizers describe current emitted forms; they do not establish current-source-to-captured-build identity, kernel-installed bytes, taken/refused call behavior, target program identity, frame correctness or useful application work. Those require their own live or previously captured evidence. Review full controller/output/diagnostics next turn; a completed process is not by itself an alignment conclusion.
