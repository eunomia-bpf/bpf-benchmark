  The application casts the integer to struct task_struct * and dereferences:
    vendor/bpf/otel/support/ebpf/tracemgmt.h:685
    vendor/bpf/otel/support/ebpf/tsd.h:42
    vendor/bpf/otel/support/ebpf/system_config.ebpf.c:73
  libbpf/BPF normally lets this pass because the loader rewrites #35 to a
  BTF-typed pointer; the stock verifier does not, and B is faithful.

  Consequently this is a decision for the B contract, not a lowering bug:
  kprog/docs/todo.md:281-285 keeps B's conservative scalar abstraction for
  unspecified/helper inputs. Typing the #35 result as a pointer needs the
  coordinator/operator to change that.

Class B: R1 unbounded memory access, before bpf_probe_read_user#112
  r11
  301: (85) call bpf_probe_read_user#112
  R1 unbounded memory access, make sure to bounds check any such access
  r1 = map_value(map=per_cpu_records) + r5, where r5 is a 64-bit shift
  (r5 <<= 6) of a value the program bounded only in 32 bits (w1 <= 0xe).
  The 32-bit bound does not carry to the 64-bit add.

Class D: R* invalid mem access 'scalar' on fentry/tracepoint programs

  Only reproduced under a BTF-aware load. On every one of these the
