# Native/eBPF source-difference audit, 2026-11-13

The two arms still differ in application semantics and helper work beyond the two previously reported cases. **The highest-priority new findings are Cilium's unconverted socket contexts, its eight-byte error in TC metadata offsets, and incorrect x86 syscall-register macros.** BCC and Tracee also suffer the previously identified CO-RE problem; it is not confined to Tetragon. Native Tetragon replaces substring kfuncs with observably different C functions and disables CEL expressions.

This report contains **23 difference groups**, not 23 newly demonstrated runtime bugs. The table separates default-path defects, conditional features, equivalent target adaptations, and inactive experiments. No production code, application source, framework, paper, design, image, kernel, base, benchmark setting, branch, or worktree was changed. No guest was started, and no performance or current-policy activation claim is inferred from a host test.

Classification: **(a)** native-target adaptation with equivalent intended behavior; **(b)** changes behavior or the operations performed; **(c)** unnecessary source divergence/removable work. A row can contain more than one class when a generally necessary adaptation has a concrete faulty case. Suggested fixes are proposals only: implement them in the native compiler/linker behind an opt-in selector first; leave the existing default and frozen eBPF build unchanged during validation. An ordinary optimization flag is not sufficient to repair an ABI, missing filter, or fault contract.

## CO-RE, helper and filter details

D04 is a general relocation defect. BCC `core_fixes.bpf.h` is byte-identical to its upstream counterpart, but compatibility processing makes its flavor `task_struct___x.__state` at offset 0 rather than target 24. `biosnoop` calls `get_disk`, whose synthetic request flavor places rq_disk at 8 and whose existence query is forced true, selecting a removed field over real request->q->disk. Regenerating the main vmlinux.h cannot repair either local flavor. Tracee's `common/task.h` similarly forces the old `pid_link` branch; the actual kernel has no `pid_link` BTF type (pahole diagnostic retained), but the application has its own compatibility definition. `common/cgroups.h:33` forces the old kernfs union branch, then a source offset through `kernfs_node___rh8`. Many other queries, including `find_vma`'s missing mm_rb check, are forced instead of resolved. No claim is made that every Tracee flavor is wrong: some capability-size/layout alternatives happen to yield the same eight bytes.

D03 changes payload values even on valid memory. On x86 syscall-entry kprobes, upstream `PT_REGS_SYSCALL_REGS` (`vendor/bpf/tetragon/bpf/libbpf/bpf_tracing.h:539`) obtains the inner pt_regs through parameter 1. Returning the outer pointer makes Tetragon's configured syscall arguments describe the wrapper rather than the syscall. Selecting the existing CORE register-read flag repairs r10 and restores nofault CORE reads, but the identity unwrap at native_compat.h:144 remains. Tracee does some explicit wrapper handling itself (`common/probes.h`), so the identity macro has a direct Tetragon call-site consequence; Tracee still reaches the arg4 mismatch. Compatibility `BPF_KSYSCALL` is a second, unused simplified alias and is not evidence of another active caller.

D05's direct capability loads remove three probe calls; namespace gathering removes helper copies and uses independent direct pointer reads. The helper branch can zero outputs after a failed read; direct loads can fault rather than return/zero, observe another value under a race, and short-circuit some reads when a pointer is null. No host test dereferenced deliberately bad kernel pointers, and this audit attributes no particular timing ratio to this source choice.

D06 can change filter truth, not just errno reporting. Kernel `vendor/linux-framework/kernel/bpf/helpers.c:3829–3882` probes memory without faults, checks address domain, stops at the haystack NUL, permits inspecting the needle terminator at `i+j==len`, and has a 64KiB iteration limit with -ENOENT/-ERANGE/-EFAULT/-E2BIG outcomes. Native's `i+j<len`/`j<100` loops, direct loads and -1 result do not implement that contract. Exact suffix and searching past NUL affect Tetragon's `idx>=0` match decision. The original eBPF generic-kprobe object has weak `bpf_strnstr`/`bpf_strncasestr` symbols; the native uses local implementations. The symbol capture in end-check.json also retains all eight unresolved `cel_expr_N` functions in the eBPF object, while the native CEL stub has no such references. The frozen policy's use of substring/CEL selectors was not measured.

The shared header does **not** implement map lookup/update/delete, queue operations, read helpers, string reads, clocks, identity getters, perf/ring output, stack capture, skb reads, signal/override, loop, IMA or argument helpers as local C bodies. Each macro casts a numbered target and calls it, or BCC uses an extern symbol. Helper IDs 1/2/3/4/5/7/8/12/14/15/16/25/26/27/35/36/37/45/58/67/68/80/87/88/95/109/112/113/114/115/125/127/130/131/132/133/134/148/158/161/173/174/175/181/183/184/185/193 were checked against the sole target header. Pointer and u64 argument widths, scalar return widths and argument order at these wrappers have no additional demonstrated ABI mismatch for simple operands. The map helper semantics still depend on linker/loader lookup specialization; the macro itself has no alternate NULL/error/bounds body. `bpf_probe_read*` delegates destination-zeroing and negative errno to the selected kernel helper. The multi-step native CO-RE macros retain intermediate probe reads; they do not turn every field read into a direct load.

**D23 prevents certifying the helper mappings as a whole.** For example, the eBPF tracepoint helper 25 is `bpf_perf_event_output_tp` (`kernel/trace/bpf_trace.c:1372`), which fetches a hidden pt_regs pointer before output. Raw tracepoints use `_raw_tp` at line 1594 and manage temporary regs/nesting. The analogous stack helpers also have typed adapters. The native link-plan table supplies the generic names, and its contextual alias list omits IDs 25/27/67. Cilium `get_socket_cookie` likewise needs the socket/sock_addr variant, not the skb variant. The native socket object also emits ID122 calls, but `kSupportedHelpers` has no get_netns_cookie entry even though x86.rs:215 recognizes it; this is a support gap, not evidence that a particular runtime invocation succeeded with that call. A correct-ID static assertion cannot validate these target selections. The fix belongs in link-plan resolution and should preserve original physical ctx for every typed helper. New live plan/address captures were outside this host-only job; source-code defects must not be renamed measured runtime error counts.

Other latent shared-header limitations are explicit: `BPF_CORE_READ_USER` with more than one accessor uses kernel reads for intermediate pointers (`native_compat.h:257–305,365`), while user reads should remain user reads throughout. Audited Tracee USER calls have one accessor, so this is not a demonstrated current multi-hop defect. `BPF_PROG2`, extra register arguments and KSYSCALL simplifications have no selected uses found. Hardcoded `bpf_ksym_exists=1` is safe only when the target kfunc is actually available; BCC's LINUX_KERNEL_VERSION is separately mapped to its kconfig map by `kprog/libnativeloader/src/native_loader.cpp:2438–2449`, so stripping __kconfig is not by itself proof of a lost value.

## Equivalent adaptations, inactive transformations and remaining limits

Every explicit native conditional is retained in [guards.json](evidence/guards.json) and assigned to a report row in [guard-review.md](evidence/guard-review.md): **67 directives**, including the shared/optional headers. This includes every requested Tracee clamp and all Tetragon native masks, context register operations, user-preload masks, generic tracepoint masks and set-if-not-errno logic. The unconditional Tetragon changes in bpf_d_path.h:148, process.h:729, event_config.h:97, generic_arg.h:36 and pfilter.h:139/160/288/449 are also in the patch, so searching only MICRO_NATIVE guards would miss them.

Tracee's C checks preserve MAX_ELEMENT_SIZE/MAX_EVENT_SIZE/MAX_SIGNAL_SIZE/FILE_MAGIC_HDR_SIZE and update_min's values. BPF `if size < max` followed by `size=max` agrees numerically with C `if size > max` at equality. Tetragon's `__do_bytes` asm `if bytes < 0` uses unsigned BPF comparison (signed is spelled `s<`), so its apparent negative branch is not evidence of a signed-negative validation removed by native. Its masking replacements preserve those actual masks. Cilium's packet-copy/checksum translations retain 0xff offset masking and -EINVAL bounds outcomes for valid buffers; native C cannot encode arbitrary pointer-wrap cases under the same verifier assumptions, so no unrestricted pointer equivalence is claimed. The Maglev array accessor's native return 0 differs from BPF's array[0] fallback when index exceeds limit; both current callers construct an in-range hash/LUT index, so that out-of-precondition difference is retained as a limitation, not a measured corpus bug.

Native CONFIG access in D17 remains `volatile const`: no rodata capture is consumed by the default build. Numeric iterators in D11 are different: their new/next/destroy helper work really disappears in native C. Native kfunc prototypes appended in native_compat.h:739 merely declare weak .ksyms symbols and do not implement their bodies; availability is a separate concern. Optimization flags such as O3, max-store thresholds or freestanding/builtin decisions belong in compiler policy and can legitimately change instruction work while preserving observable behavior. Feature defines that remove a functional application branch need pairing with the eBPF configuration instead.

No `native_specialize*.py` call occurs in `vendor/bpf/Makefile`, `runner/mk/build.mk`, or the runtime Dockerfile. `kprog/perf/one-image/Makefile:84` defaults NATIVE_MANIFEST to the image's own path.
