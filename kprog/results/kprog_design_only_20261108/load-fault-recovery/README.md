# Native load exception-table recovery

The coordinator decision of November8 gives every native memory-reading instruction the stock exception-table recovery at emission. Native bytes retain their submitted representation; the service supplies decoded load sites. A stock EX_TYPE_BPF fixup clears its selected saved GPR and advances by the native instruction length. Instructions whose destination lies outside saved GPR state use the stock resume-only encoding. The model correspondence for partial-register, ALU, vector, implicit and multiple-access fault prefixes remains explicit with laneV.

The shared service CHUNK appends load_sites_user:u64, load_site_count:u32 and reserved:u32. Each site is eight bytes: offset:u32, insn_len:u16 and destination:u16. Native ISA GPR encoding selects the saved register;0xffff selects resume-only. The existing native-link ABI sideband carries load_site rows as offset,length,destination. Final x86 code extents are decoded after relocations, covering explicit, implicit and read-modify-write reads while embedded data retains its separate extent. Chunk upload translates the emitted PC to a chunk-relative PC.

The descriptor appends num_exentries(payload) and emit_exentries(payload,rw_table,rx_table,native_ip) callbacks, preserving existing emission callback offsets. The x86 JIT counts actual normal and native entries for each final compilation pass, allocates them with its existing code/table allocation, fills their RX-relative instruction addresses through the writable alias, and publishes them under the program's existing extable lifetime. The immutable chunk retains its copied site spans with its program/capsule references.
