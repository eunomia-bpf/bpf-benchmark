## Step B: sentinel removal

Changed `KopRegistry` so target availability is explicit:

- `RegistryEntry::btf_id` is now `Option<i32>`.
- `is_target_available(target_name) -> bool` answers availability checks.
- `btf_id_for_target_name(target_name) -> anyhow::Result<i32>` returns an error when the target is unavailable.
- `set_kop_call_for_descriptor` rejects negative BTF IDs.
- `kop_registered_for_target_name` was removed.

Updated all former sentinel-style checks:

- Availability checks now call `is_target_available`.
- Emit paths now call `btf_id_for_target_name(name)?`.
- CLI target JSON and list parsing register BTF ID plus call offset through the unified setter.

Added one regression test:

- `kop_registry_reports_availability_separately_from_btf_id`

LOC impact: net positive from the new explicit availability path and regression coverage; the Step B test count increased by one. Because no interim commit was created between Step B and the later helper moves, exact Step-B-only numstat is intentionally not available from git history.

## Bytecode identity argument

The emit path logic was not changed:

- Step A only bypassed wrapper functions and calls the same registry methods directly.
- Step B changes unavailable-target handling from sentinel integer to `Result`/`bool`; successful emit paths still receive the same runtime BTF ID and call offset from `KopRegistry`.
- Step C moved functions without changing their instruction construction logic.
- `emit_packed_kop_call_with_off` still emits exactly `BpfInsn::kop_sidecar(payload)` followed by `BpfInsn::call_kop_with_off(kop_btf_id, kop_off)`.
- kop proof lookup continues to disambiguate by `(btf_id, call_off)`, preserving the P1-B fix for duplicate module-local BTF IDs.

Therefore successful pass outputs should remain byte-identical for the same input and registry state.
