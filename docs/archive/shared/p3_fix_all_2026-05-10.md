# Phase 3 Fix-All Report - 2026-05-10

## 1. P0 Fixes

### `BBProgram::split_block`
- Review source: `bpfopt/crates/bpfopt/src/analysis/bbprogram_api.rs:307-360`.
- Current: `bpfopt/crates/bpfopt/src/analysis/bbprogram_api.rs:319`.
- Change: API is now `anyhow::Result<(BlockId, BlockId)>`; previous panic/assert/expect paths were converted to `bail!` / `?`.
- Atomicity: the public method clones the full `BBProgram`, applies `split_block_in_place` to the clone, and swaps only after all validation, metadata remap, CFG rebuild, and use-def rebuild succeed.

### Transactional Mutation APIs
- Current `replace_range`: `bpfopt/crates/bpfopt/src/analysis/bbprogram_api.rs:42`.
- Current `replace_diamond_with_insns`: `bpfopt/crates/bpfopt/src/analysis/bbprogram_api.rs:375`.
- Strategy: both public APIs now clone first, mutate the candidate program, rebuild derived state there, then atomically swap the candidate into `self`. Failed replacements leave the original program unchanged.
- Related fix: `BBProgram::kop_replacement_subprog_skip_reason` now treats subprograms as frame ranges instead of treating every block start as a subprogram entry (`bpfopt/crates/bpfopt/src/analysis/bbprogram.rs:477`).

### BTF Output Errors
- Review source: `bpfopt/crates/bpfopt/src/main.rs:702-715`.
- Current: `bpfopt/crates/bpfopt/src/main.rs:705` and `main.rs:714`.
- Change: `--func-info` / `--line-info` output no longer uses `unwrap_or_default()`. Requested BTF side-output now propagates remap errors and errors if records are unavailable.

### Unknown Target Features
- Review source: `bpfopt/crates/bpfopt/src/main.rs:843-850`.
- Current: `bpfopt/crates/bpfopt/src/main.rs:854`.
- Change: unknown target features now `bail!("unknown target feature: ...")` instead of warn-and-continue.

### Other Fail-Fast Cleanup
- `attach_side_inputs` now returns `Result<()>` and the CLI propagates it (`main.rs:308`, `bbprogram.rs:613`).
- Map binding IDX resolution now errors on negative canonical indexes instead of dropping them.
- Checked liveness paths were added so invalid site/block queries fail instead of silently returning empty state.
