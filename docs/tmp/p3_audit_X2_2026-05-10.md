## Executive Summary

No scoped file has a Phase-3 migration blocker:

- No `lower(prog)` or production `BpfProgram::new` was found in the five files.
- All five production entries take `&mut BBProgram` and mutate through `replace_range`.

Remaining issues are cleanup/fail-fast quality items:

- Kinsn proof decoding/register-use boilerplate is repeated in every scoped pass.

## Cross-Pass Findings

1. Kinsn proof boilerplate is duplicated. The repeated shape is `decode_*_proof()` -> `decode_packed_kinsn_payload()` -> pass-local `*_proof_len()` -> pass-local `*_register_uses()`: `rotate.rs:24-60`, `extract.rs:17-31`, `endian.rs:53-63`, `bulk_memory.rs:34-112`, and `prefetch.rs:30-45`. This matches the wave-5 cleanup candidate. The payload formats differ, so a small shared helper should reduce wrapping/error conversion, not force a generic schema.

2. PC/site traversal helpers should move toward BBProgram APIs. `prefetch` has reusable `sites_in_frame_pc_range()` / `sites_in_block_pc_range()` at `prefetch.rs:728-764`, plus `frame_bounds()` / `block_slot_bounds()` at `prefetch.rs:766-790`. These overlap the wave-5 "ordered frame/site range helpers" candidate and existing BBProgram current-PC APIs.

3. Block-linear state reset is duplicated. `bulk_memory` resets scalar state using predecessor count, physical block order, and fallthrough terminators at `bulk_memory.rs:380-399`; `prefetch` repeats the same structure for packet state at `prefetch.rs:498-517`. A BBProgram helper for "single lexical fallthrough predecessor" would remove repeated physical-order reasoning.

4. Site structs should stop overloading `*_pc` for internal identity. `RotateSite.start_pc`, `ExtractSite.start_pc`, `EndianFusionSite.start_pc`, and `BulkSite.start_pc` are used as reporting PCs, but several scanners first populate them from local indexes before overwriting with current PCs. Keeping `InsnSite`/`idx` for identity and computing current PC only for `SkipReason`/diagnostics would make the A-rated status easier to preserve.

5. Optional candidate skips are distinct from invariant errors. Site-level safety skips are fine, but internal BBProgram errors should not become `sites_skipped`. The clearest examples are in `prefetch.rs:628-630`, `prefetch.rs:711`, and `prefetch.rs:757`; smaller examples are missing-site `Ok(None)` / `continue` paths in `extract.rs:198-200`, `endian.rs:467-482`, and `prefetch.rs:666-690`.

## ReJIT Filtering Check

Targeted `rg` over the scoped files found no forbidden ReJIT filtering patterns:

- no `live_rejit_programs`
- no `LifecycleAbort`
- no exclusion-list names
- no benchmark config pass exclusion logic
- no direct `BPF_PROG_REJIT` policy gate

The many `sites_skipped` paths are pass-local candidate rejections recorded in `PassResult`; they do not filter BPF programs out of ReJIT.

## Priority List

P0: none found in the scoped files.

P1:

1. Split `prefetch` candidate rejection from internal errors. Keep expected candidate rejections as skip reasons, but propagate BBProgram/range invariant failures instead of mapping them to `String`.
2. Make `bulk_memory` invalid-width and invalid-range cases explicit errors instead of silent `0` defaults or clamped range advancement.

P2:

1. Hoist a small kinsn proof decode helper and shared register-use helpers where it reduces boilerplate.
2. Hoist ordered frame/site PC-range helpers and block-slot bounds helpers out of `prefetch`.
3. Hoist the single-fallthrough-predecessor state-reset predicate shared by `bulk_memory` and `prefetch`.
4. Rename PC-overloaded scanner fields/arguments to `idx`/`site` internally and reserve `pc` for current-PC diagnostics/profile boundaries.
