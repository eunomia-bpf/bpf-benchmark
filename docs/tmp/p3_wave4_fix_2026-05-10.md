# Phase 3 Wave 4 Sequential Fix

Date: 2026-05-10

## 1. Tasks

### Task A: BBProgram fail-fast + atomicity

Done:

- `delete_insn`, `delete_cond_branch`, `replace_terminator`, and `permute_blocks` now mutate a cloned `BBProgram` and swap only after validation/rebuild succeeds.
- Duplicate kop target registration now returns `anyhow::Result` instead of panicking. Production callers use `try_baseline()` / `KopRegistry::unavailable()?`; the panic-only `Default` registry constructor is test-only.
- Unchecked liveness/BTF query shims (`live_in`, `live_out`, `live_out_site`, `btf_records`) are now `#[cfg(test)]`; checked APIs remain production-visible.

LOC delta from unstaged wave-4 diff: `+46` LOC across `bbprogram_api.rs`, `bbprogram.rs`, `bbprogram_lift.rs`, `pass.rs`, and `main.rs`.

### Task B: map_inline B-to-A core

Done:

- `MapInlineView::subprog_bounds()` is fail-fast and returns `anyhow::Result`; the whole-program fallback is gone.
- `MapInlineView` no longer stores or imports `ProgramLinearView`; it builds its current slot stream directly from BBProgram sites and preserves `pc -> InsnSite` only for verifier/hint/diagnostic correlation.
- `lookup_call_pcs` was replaced with `lookup_call_sites`.
- map reference metadata is keyed by `InsnSite` via `MapReference.site` and `MapInfoResult::reference_at_site()`. Production `reference_at_pc()` is gone.
- resolved inline hints are keyed by call `InsnSite`, not call PC.

### Task C: map_inline rewrite-plan cleanup

Done:

- `SiteRewrite.skipped_pcs: HashSet<usize>` was replaced with `skipped_sites: BTreeSet<InsnSite>`.
- Rewrite conflict detection and apply-time deletion now operate directly on `InsnSite`; the apply path no longer converts PC sets to sites.
- Lookup-removal safety scans and null-check guarded window checks now iterate same-program site order rather than raw PC slot ranges.
- Replacement planning uses `InsnSite` for fixed-load replacements, call replacements, null-check replacements, and map-in-map outer-only replacements.
- Remaining fallible site/PC correlations in map_inline propagate errors; `.ok()` conversions were removed from production `map_inline.rs`.

LOC delta for Tasks B+C from unstaged wave-4 diff: `+172` LOC across `map_inline.rs` and `map_inline/map_info.rs`.
