# Phase 3 Wave 3 Codex 2+3 Report

Date: 2026-05-10

## 1. map_inline.rs LOC

- Before: 5724 LOC
- After: 5573 LOC
- Net: -151 LOC

Removed or collapsed:

- Deleted the private `MapInlineProgram` re-emission adapter name and its private `pc_to_site` map.
- Replaced private full-program re-emission with `BBProgram::program_linear_view()`.
- Removed `subprog_ranges: Vec<(usize, usize)>`; bounds are keyed by `FrameId` and built from `prog.subprog_blocks(frame)`.
- Removed `current_block_end_pcs`, `current_subprog_ranges`, `emit_current_terminator`, and local `pc_delta`.
- Removed `raw_map_lookup_call_pcs_flat`; lookup call PCs are collected from `prog.blocks()` / `prog.sites_in_block()`.
- Direct pseudo-map-value load rewrite now iterates BBProgram blocks/sites and gets the instruction with `prog.insn_at(site)`.
- `apply_map_inline_edit` is clone-swap atomic.

## 2. map_inline Rating

Still B, not A.

Evidence: the private re-emission adapter is gone, but `MapInlineView` still carries a `ProgramLinearView`, and the deeper local dataflow helpers still use current-PC indexing through `program.linear.insns` for backward scans, null-check windows, and key/pointer resolution. That is materially smaller and safer than wave 2, but it is not fully BBProgram-native yet.

Soft-fold guard path remains fail-closed with `soft fold requires BBProgram CFG insertion`; no CFG insertion API was added in this wave.
