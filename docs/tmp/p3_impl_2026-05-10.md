# Phase 3 BBProgram Migration Implementation Report

Date: 2026-05-10

## Step Results

1. BBProgram native methods: implemented computed-on-call `live_in`, `live_out`, `dominance`, `reaching_defs`, `map_bindings`, `subprog_blocks`, `btf_records`, `unreachable_blocks`, `sites_in_block`, and `sites_in_block_with_terminator`. Added side-input attachment and BTF remap helpers. Approx. new BBProgram core: 2,510 LOC across `bbprogram*.rs`.
2. PassContext + BpfPass boundary: changed `BpfPass::run` to `fn run(&self, program: &mut BBProgram, ctx: &PassContext) -> Result<PassResult>`. CLI now lifts once, runs passes on BBProgram, lowers once, and carries side inputs through `PassContext`. Approx. net touched area: `pass.rs` / `main.rs` / pass adapters.
3. PassContext side inputs: moved verifier states, annotations, branch PMU data, maps, map values, overlays, map-in-map data, skipped snapshots, map-inline hints, BTF func/line info, registry, platform, policy, and prog type onto `PassContext`.
4. Pass migration: all CLI-dispatched passes now enter through `BpfPass::run(&mut BBProgram, &PassContext)`. C-rated passes still retain some legacy linear helper usage internally, but no pass trait accepts `BpfProgram`.
5. map_inline: added BBProgram adapter, moved side inputs from `PassContext`, preserves hard-vs-soft hint semantics, map-in-map fail-fast cases, kernel-mutability skips, compressed overlays, and verifier-guided key behavior.
6. B-rated pass polish: const_prop now mutates BBProgram directly and dropped stale address-map replacement bookkeeping; branch_flip validates lowered branch ranges through the BBProgram lower path; bounds/dce/map-inline paths preserve BTF/lower remaps through BBProgram.
7. Old analyses: not deleted. `branch_target`, `cfg`, `liveness`, `map_refs`, and `site_scan` remain because current pass internals and compatibility tests still consume them.
8. bbprogram_api trim: deleted zero-caller public APIs `replace_insn`, `insert_insn`, `delete_block`, `rewire_edge`, and `replace_diamond_with_kinsn`; removed public `range_len` re-export.
9. BTF remap: centralized BBProgram lowered BTF record views in `bbprogram.rs`/`bbprogram_lower` flow for test-facing APIs and CLI BTF output.
10. pass.rs slim: `BpfProgram` remains as a legacy bytecode carrier for map snapshot/provider compatibility; `PassManager` now iterates BBProgram passes.
